# Contributing to the TensorGuard benchmark leaderboard

The leaderboard ([`reproducibility/leaderboard.md`](../../reproducibility/leaderboard.md),
generated by [`reproducibility/leaderboard.py`](../../reproducibility/leaderboard.py))
scores tools on the frozen, content-addressed ground-truth corpus in
`real_benchmarks/`. Every case is a real PyTorch `nn.Module` labelled `clean`
(should verify SAFE) or `buggy` (should verify UNSAFE), pinned by sha256 so the
benchmark cannot silently drift.

There are two ways to contribute.

## 1. Add a benchmark case

Make the corpus harder and more representative.

1. Add a real module file under `real_benchmarks/clean/<id>.py` or
   `real_benchmarks/buggy/<id>.py`. A `clean` case **must execute without error
   in eager PyTorch**; a `buggy` case must fail (or mistrain) for a reason in
   TensorGuard's modeled scope (shape / device / gradient).
2. Describe it in `real_benchmarks/corpus_def.py` (id, label, domain,
   `input_shapes`, `expected_verdict`, provenance, and for buggy cases the
   `expected_error_substring`).
3. Re-freeze the manifest:

   ```bash
   PYTHONPATH=. python3 real_benchmarks/build_manifest.py
   ```

   This recomputes each file's sha256 and writes `real_benchmarks/manifest.json`.
   `real_benchmarks/load.py` re-verifies every hash on load, so a frozen case
   can never change underneath a scorecard.

Cases should be **minimal and self-contained** (one architectural idea each)
and carry honest provenance. Synthetic cases are welcome but should mirror a
real-world mistake.

## 2. Submit a tool entry

Score any verifier — yours or a baseline — without trusting its self-reported
numbers. Drop a JSON file in `benchmarks/leaderboard_entries/<tool>.json`:

```json
{
  "tool": "my-verifier",
  "description": "One-line description of the tool / mode.",
  "url": "https://github.com/you/my-verifier",
  "verdicts": {
    "clean_mlp": "SAFE",
    "buggy_linear_inout_mismatch": "UNSAFE",
    "buggy_view_total_size": "UNKNOWN"
  }
}
```

* Keys are corpus case ids (see `real_benchmarks/manifest.json`); values are
  `SAFE`, `UNSAFE`, or `UNKNOWN` (abstention).
* A missing id is treated as `UNKNOWN`.
* The leaderboard **recomputes** recall / precision / F1 / accuracy from these
  raw verdicts — submitters cannot self-report inflated metrics; only the
  per-case verdicts are trusted.

Scoring rules:

* **Buggy** case → true positive iff verdict is `UNSAFE`. `SAFE` or `UNKNOWN`
  counts as a miss (lowers recall). `UNKNOWN` is tracked separately as an
  abstention.
* **Clean** case → false positive iff verdict is `UNSAFE`. `UNKNOWN` on a clean
  case is *not* a false alarm.
* Entries are ranked by F1, then recall, then precision.

A committed example, `benchmarks/leaderboard_entries/trivial-always-safe.json`,
shows the format: a trivial always-SAFE baseline that scores recall 0 — the
floor the field has to beat.

### The bar

**Precision must stay at 1.000.** A single false alarm on a clean module is
disqualifying for a tool meant to ship inside a framework. The open challenge
is to drive **recall** up on ever-harder real-world bugs while keeping that
zero-false-alarm guarantee. Regenerate after any change:

```bash
PYTHONPATH=. python3 reproducibility/leaderboard.py          # regenerate
PYTHONPATH=. python3 reproducibility/leaderboard.py --check   # assert determinism
```

### CI validation of submissions

Every PR that touches `benchmarks/leaderboard_entries/**` runs
[`.github/workflows/leaderboard.yml`](../../.github/workflows/leaderboard.yml),
which:

1. validates each entry with
   [`reproducibility/validate_entry.py`](../../reproducibility/validate_entry.py)
   — rejecting unknown case ids, bad verdict tokens, a missing `tool`/`verdicts`,
   and any **self-reported metric field** (`recall`, `f1`, `scorecard`, …): only
   the raw per-case verdicts are accepted, scoring is recomputed;
2. re-scores the whole leaderboard from those verdicts;
3. asserts the regenerated artifact is byte-deterministic (`--check`).

So a submission can never inflate its own numbers or silently corrupt the board.
