# Third-party acceptance governance

TensorGuard accepts outside contributions only when the review path is tied
to a real verifier gate. This page is generated by
`reproducibility/governance_acceptance.py`; the companion audit proves that
each cited script, workflow, document, and symbol resolves in this repo.

Gate kinds are deliberately explicit: **automated** means CI or a local
command can enforce the requirement; **maintainer-judgment** means the
requirement is a human review obligation backed by `GOVERNANCE.md`,
`SECURITY.md`, or `MAINTAINERS.md`.

## Verifier / SMT backend submissions

Alternative solver backends or verifier-backend experiments must implement the shared SMT interface and prove concordance on the decidable VC fragments TensorGuard emits.

### Required surfaces

- `docs/decidability/smt_backends.md` — present
- `reproducibility/smt_backend_comparison.py` — present
- `src/smt/cvc5_backend.py` — present
- `src/smt/solver.py` — present
- `tests/test_smt_backend_comparison.py` — present

### Maintainer checklist

| Gate | Kind | Checklist item | Evidence |
| --- | --- | --- | --- |
| Shared backend interface | automated | Implement `SmtSolver`/`check_sat` semantics without changing the predicate IR. | `src/smt/solver.py` |
| Cross-backend concordance | automated | Run the Z3/cvc5 concordance harness and keep every VC verdict identical. | `reproducibility/smt_backend_comparison.py`, `tests/test_smt_backend_comparison.py` |
| Security and governance review | maintainer-judgment | Confirm no new trust boundary, network access, or model-code execution path is introduced. | `GOVERNANCE.md`, `MAINTAINERS.md`, `SECURITY.md` |

### Maintainer checklist

## Leaderboard and benchmark-result submissions

External tool results are accepted as signed raw per-case verdicts; TensorGuard recomputes all metrics and rejects self-reported scores.

### Required surfaces

- `.github/ISSUE_TEMPLATE/leaderboard_submission.md` — present
- `.github/workflows/leaderboard.yml` — present
- `benchmarks/leaderboard_entries/allowed_signers` — present
- `docs/leaderboard/CONTRIBUTING.md` — present
- `reproducibility/leaderboard.py` — present
- `reproducibility/validate_entry.py` — present

### Maintainer checklist

| Gate | Kind | Checklist item | Evidence |
| --- | --- | --- | --- |
| Signed raw verdicts only | automated | Validate case ids, uppercase verdict tokens, SSH signatures, and absence of self-reported metrics. | `.github/workflows/leaderboard.yml`, `benchmarks/leaderboard_entries/allowed_signers`, `reproducibility/validate_entry.py` |
| Recomputed deterministic leaderboard | automated | Regenerate and byte-check the leaderboard from raw verdicts. | `docs/leaderboard/CONTRIBUTING.md`, `reproducibility/leaderboard.py` |
| Anti-overfitting disclosure | maintainer-judgment | Review benchmark-specific tuning, abstention policy, and monthly refresh-window eligibility. | `.github/ISSUE_TEMPLATE/leaderboard_submission.md`, `MAINTAINERS.md`, `docs/leaderboard/CONTRIBUTING.md` |

## Acceptance rule

A submission is mergeable only when every automated gate passes and the
maintainer-judgment gates have an explicit reviewer sign-off in the PR.
If a gate cannot be run in the contributor's environment, the PR must carry
the exact skipped command and a maintainer-owned reproduction note.
