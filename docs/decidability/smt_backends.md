# SMT backends: Z3 vs cvc5, and the decidability of TensorGuard's VCs

TensorGuard's verifier is **backend-agnostic**. Every verification condition (VC)
is built in the shared predicate IR of `src/smt/solver.py` and discharged by
either the Z3 backend (`Z3Solver`) or the cvc5 backend
(`src/smt/cvc5_backend.py::CVC5Solver`). Soundness must not depend on *which*
solver runs. This note records the decidability classification of the VC
fragments and the measured Z3/cvc5 concordance.

## 1. Which theory fragments do shape VCs land in?

`src/decidability.py` classifies each VC by the operations it contains:

| Reasoning pattern | Theory fragment | Decidability |
| --- | --- | --- |
| matmul inner-dim, Linear arity, cat non-cat dims, broadcast | QF_LIA (linear integer arithmetic) | decidable, **P** |
| device consistency | finite domain (a handful of device ids) | decidable, **P** |
| phase (train/eval) consistency | finite domain (Boolean) | decidable, **P** |
| reshape / flatten total-size (product equality `m*n*... == T`) | NIA (nonlinear integer arithmetic) | **NP-hard** (SUBSET-PRODUCT reduction), still decidable here |

The linear shape constraints combine with the finite device/phase theories by
the Nelson-Oppen / Tinelli-Zarba arrangement argument, which stays polynomial in
the shared variables for finite domains. The only source of NP-hardness is the
product-equality introduced by `reshape`/`flatten`; crucially it remains
**decidable** (the products are over bounded dimension variables), so both
solvers must -- and do -- return a verdict.

## 2. Measured Z3/cvc5 concordance

[`reproducibility/smt_backend_comparison.py`](../../reproducibility/smt_backend_comparison.py)
runs a curated suite of VCs -- one satisfiable and one unsatisfiable instance per
reasoning pattern above -- through **both** backends and checks that (a) each
solver returns the intended verdict and (b) the two solvers agree. The generated
table is
[`reproducibility/smt_backend_comparison.md`](../../reproducibility/smt_backend_comparison.md);
it is regenerated byte-identically by `reproducibility/reproduce_all.py --check`.

Result on the committed suite:

- **14 VCs** (12 decidable in P, 2 NP-hard NIA reshape/flatten).
- **Z3 returns the intended verdict on every VC.**
- **cvc5 returns the intended verdict on every VC.**
- **Z3 and cvc5 are in full concordance -- identical SAT/UNSAT on all 14 VCs,
  including the NP-hard NIA fragment.**

Any disagreement, or either solver being wrong, would be a **trust-boundary
failure**: it would mean the verifier's soundness depends on an SMT-solver
idiosyncrasy. The cross-check rules that out on the patterns the verifier emits.

## 3. Performance trade-offs (qualitative)

On these VCs both solvers answer in well under a millisecond, so we do **not**
record timings in the byte-diffed artifact (they are machine-dependent and would
break determinism). The relevant engineering trade-off is interface, not speed:

- **Z3 is the default** because the DPLL(T)-style shape propagators use Z3's
  `UserPropagator` callback interface (incremental theory propagation with
  push/pop). cvc5 does not expose an equivalent push/pop propagator callback.
- **cvc5 is the independent oracle.** Running cvc5's *built-in* theory reasoning
  to the same verdicts shows the results are not an artifact of Z3's propagators
  -- a stronger soundness story than a single-solver pipeline.

## 4. Reproducing

```bash
cd tensorguard && . .venv/bin/activate
PYTHONPATH=. python3 reproducibility/smt_backend_comparison.py          # regenerate
PYTHONPATH=. python3 reproducibility/smt_backend_comparison.py --check  # assert determinism
python3 -m pytest tests/test_smt_backend_comparison.py -q               # both-backend tests
```

The decidability classifiers live in `src/decidability.py`; the two backends
share the `SmtSolver` interface in `src/smt/solver.py`.
