01 What TensorGuard Catches

Eight classes of bugs across three theory domains, all detected statically with zero annotations.

📐

Shape Mismatches

nn.Linear input dimension ≠ declared in_features. Conv output flattened to wrong Linear input. Matmul inner dimension incompatibility.

🔀

Bad Reshape / View

x.view(batch, -1) where total elements don't divide evenly. Reshape product-equality violations verified via Z3 QF_NIA constraints.

📦

Broadcast Errors

torch.cat([a, b], dim=1) with different sizes on non-cat dims. Broadcasting shape incompatibility in element-wise operations.

💻

Device Mismatches

cpu_tensor + cuda_tensor — catches silent CPU↔CUDA mismatches. Detects buffers that stay on CPU after model.cuda().

🔄

Phase Errors

model.eval() then calling layers that behave differently. Train-head vs eval-head dimension mismatches in transfer learning.

🧮

Stride / Permutation

Contiguity assumptions violated after transpose/permute. Memory layout correctness for view operations.

🔗

Cross-Theory Bugs

Shape × Device × Phase interactions — e.g., anchor buffer with wrong spatial dims AND wrong device AND only used in eval mode.

🎯

Dead Code Detection

Computed results that are never used or returned. Variables assigned but overwritten before any read.

03 Formal Foundations

TensorGuard's verification is grounded in refinement type theory, SMT theory combination, and abstract interpretation.

Refinement Types for Tensors

Each tensor carries a refinement type — a base type annotated with logical predicates from five theories. Subtyping reduces to logical implication, checked via Z3.

Definition — Tensor Refinement Type
$$\{t : \mathit{Tensor} \mid \varphi_{\mathit{shape}} \land \varphi_{\mathit{device}} \land \varphi_{\mathit{phase}} \land \varphi_{\mathit{stride}} \land \varphi_{\mathit{perm}}\}$$
A tensor refined by five theory predicates: shape constraints, device location, training phase, memory stride, and permutation state.
Rule — Subtyping via Implication
$$\{t : T \mid \phi\} \leq \{t : T \mid \psi\} \quad\text{iff}\quad \phi \Rightarrow \psi \text{ is valid}$$
Subtyping is checked by asking Z3 whether $\phi \land \neg\psi$ is UNSAT. If so, every value satisfying $\phi$ also satisfies $\psi$.

Five-Theory Product Domain

TensorGuard jointly reasons over five theory domains. Each provides its own signature, axioms, and decision procedure. They are combined via Tinelli–Zarba finite-domain theory combination.

Domain — Shape Theory $\mathcal{T}_{\text{shape}}$
$$\Sigma_{\mathit{shape}} = \left\{\; \mathit{dim}_i : \mathit{Tensor} \to \mathbb{Z}_{\geq 1},\;\; \mathit{ndim} : \mathit{Tensor} \to \mathbb{N},\;\; \mathit{prod} : \mathit{Dim}^* \to \mathbb{Z}_{\geq 1},\;\; \mathit{broadcast} : \mathit{Dim}^* \times \mathit{Dim}^* \to \mathit{Dim}^* \;\right\}$$
Encodes tensor dimensions as positive integers. Broadcasting, reshape, and slicing are axiomatized over this signature.
Axiom — Broadcasting Compatibility
$$\forall i.\; s_a[i] = s_b[i] \;\lor\; s_a[i] = 1 \;\lor\; s_b[i] = 1$$
Two shapes are broadcast-compatible when, at every aligned dimension, they are equal or one of them is 1.
Domain — Device Theory $\mathcal{T}_{\text{device}}$
$$\Sigma_{\mathit{device}} = \left\{\; \mathit{dev} : \mathit{Tensor} \to \mathcal{D} \;\right\} \qquad \mathcal{D} = \{\texttt{cpu}, \texttt{cuda:0}, \texttt{cuda:1}, \ldots\}$$
Tracks tensor device placement. All operands of an operation must reside on the same device.
Domain — Phase Theory $\mathcal{T}_{\text{phase}}$
$$\Sigma_{\mathit{phase}} = \left\{\; \mathit{mode} : \mathit{Context} \to \mathcal{P},\;\; \mathit{active} : \mathit{Op} \times \mathcal{P} \to \mathbb{B} \;\right\} \qquad \mathcal{P} = \{\texttt{train}, \texttt{eval}\}$$
Models train/eval phase-dependent behavior. Dropout is only active in train mode; BatchNorm uses running statistics in eval.
Domain — Stride Theory $\mathcal{T}_{\text{stride}}$
$$\mathit{contiguous}(t) \;\iff\; \forall i < \mathit{ndim}(t) - 1.\;\; \mathit{stride}_i(t) = \mathit{stride}_{i+1}(t) \cdot \mathit{dim}_{i+1}(t)$$
Tracks memory layout. Operations like view() require contiguous memory; transpose breaks contiguity.
Domain — Permutation Theory $\mathcal{T}_{\text{perm}}$
$$\mathsf{swap}(\mathsf{swap}(s, i, j), i, j) = s \qquad\qquad |\mathsf{apply}(\pi, s)| = |s|$$
Permutation involution and bijectivity axioms. Tracks dimension reordering through permute() and transpose().

Cross-Domain Interaction Axioms

Axiom — Device Incompatibility
$$\mathit{dev}(a) \neq \mathit{dev}(b) \implies \neg\,\mathit{compatible}(a, b)$$
Tensors on different devices cannot participate in the same operation.
Axiom — Phase-Conditional Behavior
$$\mathit{mode} = \texttt{eval} \implies \mathit{dropout\_active} = \mathit{false}$$
Phase predicates constrain which operations are active, enabling detection of phase-dependent shape errors.

Operator Transfer Functions

Each PyTorch operation has a transfer function that maps input types to output types. These are the core of TensorGuard's shape propagation — 142 operators are covered.

Transfer Function — Linear Layer
$$\Gamma \vdash \texttt{Linear}(f_{\text{in}}, f_{\text{out}})(x) \;:\; \{t' \mid \mathit{shape}(t') = \mathit{shape}(x)_{[0:-1]} \;\|\; [f_{\text{out}}]\}$$
Linear replaces the last dimension: input must have last dim = $f_{\text{in}}$, output has last dim = $f_{\text{out}}$.
Transfer Function — Conv2d
$$\mathit{dim}_i(t') = \left\lfloor\frac{\mathit{dim}_i(x) + 2p - d(k-1) - 1}{s}\right\rfloor + 1$$
Standard convolution output dimension formula, parameterized by padding $p$, dilation $d$, kernel size $k$, stride $s$.
Transfer Function — Reshape / View
$$\prod_i s_i = \prod_j d_j$$
Product-equality constraint: the product of input dimensions must equal the product of output dimensions. Falls in QF_NIA (NP-hard) when dimensions are symbolic.
Transfer Function — Concatenation
$$\mathit{dim}_d(t') = \sum_i s_i[d]$$
Concatenation sums along axis $d$; all other dimensions must match exactly.
Transfer Function — Matmul
$$\mathit{shape}(t') = \mathit{broadcast}(s_A[:-2],\; s_B[:-2]) \;\|\; [s_A[-2],\; s_B[-1]]$$
Batch dimensions are broadcast; inner dimensions must match: $s_A[-1] = s_B[-2]$.
Transfer Function — Phase-Conditional
$$\Gamma \vdash \texttt{if self.training:}\; e_1 \;\texttt{else:}\; e_2 \;:\; \tau_1 \sqcap \tau_2$$
Both branches are verified independently. The result type is the meet (intersection) of both branch types.

Theory Combination

The five theories are combined using the Tinelli–Zarba method for finite-domain theories. Arrangements enumerate possible equalities between shared variables.

Method — Tinelli–Zarba Arrangement Enumeration
$$\text{arrangement} = \text{partition of shared variables into } \leq n \text{ equivalence classes}$$
For each arrangement, each theory's decision procedure checks consistency. If all agree on at least one arrangement, the conjunction is satisfiable.
Complexity — Arrangement Bound
$$S(k_d, 5) \cdot S(k_p, 2)$$
Stirling numbers of the second kind bound the number of arrangements for $k_d$ device variables over 5 device values and $k_p$ phase variables over 2 phases.

Soundness & Decidability

Theorem — Product Domain Soundness

Let $\mathcal{T}_{\Pi} = \mathcal{T}_{\text{shape}} \times \mathcal{T}_{\text{device}} \times \mathcal{T}_{\text{phase}} \times \mathcal{T}_{\text{stride}} \times \mathcal{T}_{\text{perm}}$. If $\Gamma \vdash e : \tau$ and $\sigma \models \Gamma$, then $e$ does not produce a shape, device, phase, stride, or permutation error at runtime.

Theorem — CEGAR Convergence

The predicate-refinement loop terminates in at most $|P_0|$ iterations, where $P_0$ is the initial predicate candidate set generated from the template grammar: $$P ::= d_i = c \;\mid\; d_i = d_j \;\mid\; d_i = k \cdot d_j \;\mid\; d_i + d_j = d_k$$

Theorem — Abstract Interpretation Soundness

The abstract transformer $\llbracket G \rrbracket^\sharp$ is a sound over-approximation of the concrete semantics: $$\alpha(\llbracket G \rrbracket(\sigma)) \sqsubseteq \llbracket G \rrbracket^\sharp(\alpha(\sigma))$$ where $\alpha$ is the abstraction function of the Galois connection $(\alpha, \gamma)$ between concrete tensor states and abstract shape predicates.

Z3 SMT Encoding

Constraints are encoded directly into Z3's SMT-LIB language. Here are representative encodings.

Linear Layer Encoding
# Z3 constraints for nn.Linear(128, 64)
# Input x must have last dim = 128
(assert (= x_dim_last 128))
# Output preserves all dims except last
(assert (= y_ndim x_ndim))
# Output last dim = out_features
(assert (= y_dim_last 64))
Conv2d Encoding
# Z3 constraints for nn.Conv2d(3, 64, 7, stride=2, padding=3)
(assert (= x_dim1 3))                                    ; in_channels
(assert (= y_dim0 x_dim0))                                ; batch preserved
(assert (= y_dim1 64))                                    ; out_channels
(assert (= y_dim2 (+ (div (- (+ x_dim2 6) 7) 2) 1)))    ; spatial H
(assert (= y_dim3 (+ (div (- (+ x_dim3 6) 7) 2) 1)))    ; spatial W
Device + Phase Cross-Theory
# Cross-domain constraint encoding
(assert (= x_device 1))          ; x on CUDA
(assert (= buf_device 0))        ; buffer on CPU
(assert (= x_device buf_device)) ; CONFLICT → device mismatch detected

# Phase-conditional shape check
(assert (=> (= mode 0)           ; train mode
    (= train_out_dim 100)))
(assert (=> (= mode 1)           ; eval mode
    (and (= backbone_dim 128)
         (= eval_out_dim 10))))   ; must match backbone output

CEGAR Algorithm

⚙️ Algorithm 1: Counterexample-Guided Abstraction Refinement
function CEGAR(Graph $G$, InitPredicates $P_0$, MaxIter $k$):
$P \leftarrow P_0$ // initial predicate set from template grammar
for $i = 1$ to $k$:
$\mathit{result} \leftarrow$ Verify($G$, $P$) // Z3 constraint check with current predicates
if $\mathit{result} = \texttt{SAFE}$:
return $(\texttt{SAFE}, P)$ // proved safe with predicates $P$
$\mathit{cex} \leftarrow$ ExtractCounterexample($\mathit{result}$)
if IsGenuine($\mathit{cex}$):
return $(\texttt{UNSAFE}, \mathit{cex})$ // real bug found
$P' \leftarrow$ RefinePredicates($\mathit{cex}$, $P$) // discover new predicates
$P \leftarrow P \cup P'$
return $(\texttt{UNKNOWN}, P)$ // exhausted iterations

Shape Mismatch — Conv→Linear Dimension Error

model.py
class BuggyModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Conv2d(3, 128, 3, padding=1)
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.fc = nn.Linear(256, 10)   # ← BUG: expects 256, conv outputs 128

    def forward(self, x):
        x = self.conv(x)              # → [B, 128, H, W]
        x = self.pool(x)              # → [B, 128, 1, 1]
        x = x.flatten(1)              # → [B, 128]
        return self.fc(x)             # 💥 Linear expects 256, got 128

class TransferLearningBug(nn.Module):

class FPNBug(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone_c3 = nn.Conv2d(3, 128, 3, padding=1)
        self.backbone_c4 = nn.Conv2d(128, 256, 3, stride=2, padding=1)
        self.backbone_c5 = nn.Conv2d(256, 512, 3, stride=2, padding=1)

            + F.interpolate(p5, scale_factor=2)
        return p4

Squeeze-Excitation Block — Stale Channel Count

senet.py
class SEBlockBug(nn.Module):
    def __init__(self, channels=512, reduction=16):
        super().__init__()
        self.conv = nn.Conv2d(3, channels, 3, padding=1)   # outputs 512
        self.pool = nn.AdaptiveAvgPool2d(1)
        # BUG: SE block was designed when channels=256, never updated
        self.se_fc1 = nn.Linear(256, 256 // reduction)
        self.se_fc2 = nn.Linear(256 // reduction, 256)
        self.relu = nn.ReLU()
        self.sigmoid = nn.Sigmoid()

    def forward(self, x):
        out = self.conv(x)                                  # [B, 512, H, W]
        se = self.pool(out).view(out.size(0), -1)           # [B, 512]
        se = self.relu(self.se_fc1(se))                     # 💥 512 ≠ 256
        se = self.sigmoid(self.se_fc2(se))
        return out * se.unsqueeze(-1).unsqueeze(-1)

class CorrectMultiTheory(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Conv2d(3, 64, 3, padding=1)
        self.bn = nn.BatchNorm2d(64)
        self.fc = nn.Linear(64, 10)
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.dropout = nn.Dropout(0.5)

    def forward(self, x):
        x = F.relu(self.bn(self.conv(x)))   # [B, 64, H, W]  ✓
        x = self.pool(x)                     # [B, 64, 1, 1]  ✓

        if self.training:
            x = self.dropout(x)              # shape-preserving ✓
        return self.fc(x)                    # [B, 64] → [B, 10] ✓

06 Getting Started

Install TensorGuard and verify your first model in under a minute.

Installation

Terminal
git clone https://github.com/thehalleyyoung/tensorguard.git
cd tensorguard
pip install -e .

Only dependency: z3-solver≥4.12 (installed automatically).

CLI Usage

Verify a model
# Verify with explicit input shape
$ tensorguard verify model.py -s x=batch,3,224,224

# JSON output for CI
$ tensorguard verify model.py --format json

# SARIF for GitHub Code Scanning
$ tensorguard ci-check models/ --sarif-output results.sarif

# High-confidence mode (0% false positives)
$ tensorguard verify model.py --high-confidence

Python API

api_example.py
from src.api import verify_module

result = verify_module(
    "model.py",
    input_shapes={"x": ("batch", 3, 224, 224)},
    check_devices=True,
    check_phases=True,
)

print(f"Status: {result.status}")        # "SAFE" or "UNSAFE"
print(f"Bugs: {result.bug_count}")
print(f"Time: {result.duration_ms:.0f}ms")

for bug in result.bugs:
    print(f"  L{bug.location.line}: {bug.message}")
