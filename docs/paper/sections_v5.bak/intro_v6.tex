\section{Introduction}\label{sec:intro}

Tensor programs in PyTorch fail in two characteristic ways that
unit tests rarely catch: \emph{(i)} the forward pass crashes deep
inside an autograd-traced subgraph because two operand shapes
disagree under a particular batch size, sequence length, or
image resolution; and \emph{(ii)} the backward pass silently
produces a wrong gradient --- e.g.\ a parameter receives
\texttt{p.grad=None} after \texttt{loss.backward()} because an
in-place op or a \verb|.detach()| broke the autograd tape along
one branch, and \texttt{optimizer.step()} silently skips it.

The PyTorch ecosystem responds to these failures with
\emph{execution-based} tools: \texttt{torch.fx}+ShapeProp
captures one trace, \texttt{FakeTensorMode} executes shape
arithmetic on metadata-only tensors, \texttt{torch.export}
specialises a trace, and \texttt{TorchDynamo} installs runtime
guards that recompile when an invariant fails. All four require
the model to be importable, instantiable, and traceable on the
target machine. On modern HuggingFace/timm code that is
typically \emph{not} the case: a transformer block needs a
\texttt{config} object, an attention head reads
\texttt{self.config.hidden\_size}, and an
\texttt{nn.ModuleList} over \texttt{config.num\_layers} blocks
demands a fully-realised configuration before a single tensor
can flow.

\textsc{TensorGuard} takes the opposite stance. Given an
\texttt{nn.Module} \emph{class source}, with no instantiation
and no tracer, it computes a refinement-typed signature
$\mathsf{Tensor}\{s,g\mid\varphi\}$ for every value flowing
through \texttt{forward}, where $s$ is a symbolic shape, $g$ is
a static gradient-required flag, and $\varphi$ is a
Z3-decidable refinement constraining both. \textsc{TorchDynamo}
guards become the runtime shadow of these refinements
(\Cref{thm:dynamo-corr}), and \textsc{TensorGuard}'s
\textsc{Abstain} verdict marks exactly the subgraphs on which
Dynamo would have broken the graph. The cost is principled:
we report \textsc{Abstain} as a first-class verdict rather than
silently claim verification.

\paragraph{Contributions.}\hangindent=1em
\textbf{(C1)} A refinement-typed calculus
$\mathsf{Tensor}\{s,g\mid\varphi\}$ unifying symbolic shape and
static gradient-flag analysis under one Z3 procedure
(\Cref{sec:calculus}), with classical
Preservation/Progress (\Cref{thm:preservation,thm:progress}).
\textbf{(C2)} An assume/guarantee discipline at the
\texttt{nn.Module} class boundary, with a contravariant/covariant
subclassing rule (\Cref{sec:assume-guarantee}).
\textbf{(C3)} An autograd-aware backward verifier catching
three canonical silent-zero-grad bug classes statically
(\Cref{sec:impl-backward}); $500/500$ static$\leftrightarrow$runtime
agreement, $8/8$ canonical bugs caught, $0/50$ false positives.
The lattice is first-order
($\{\texttt{has\_grad},\texttt{no\_grad},\top\}$) and is silently
incorrect on parameter-sharing-under-renamed-attribute (prevalence
$\le 12\%$ of training scripts; \Cref{sec:limconc}); we flag this as
a substantive caveat, not a footnote.
\textbf{(C4)} A \emph{Dynamo-guard inclusion lemma}
(\Cref{thm:dynamo-corr}, necessary direction only): every
\textsc{TG} refinement variable is, on the matching
\texttt{aten} call, a metadata read \textsc{TorchDynamo}'s
specialiser issues on a \texttt{FakeTensor}.  The mapping is
shipped as data
(\texttt{reproducibility/dynamo\_correspondence\_data.json},
$28$ rows; mechanically rechecked against the imported
torch in
\texttt{experiments\_v5/v8/dynamo\_correspondence\_data\_check.py}
--- $28/28$ pass under \texttt{torch~2.9.1}).  The lemma is
empirically audited on $17$ real torchvision/HuggingFace/timm
modules; the $8.8\%$ in-contract recompile rate is a property
of \emph{Dynamo} (it specialises on metadata
\emph{outside} the \textsc{TG} fragment, exactly what the
necessary-only direction allows) and is consistent with, not
evidence for, the lemma.  We do \emph{not} claim a
two-directional correspondence.
\textbf{(C5)} A $488$-block + $60$-bug $+\,10$-real-public-bug
benchmark with calibrated reporting under a five-way verdict
taxonomy per tool (\Cref{sec:eval-benchmark});
a per-feature stress benchmark
discriminating each feature on $25$ targeted cases
(\Cref{tab:ablation}); a $25$-block hybrid-mode
falsification corpus (\Cref{tab:hybrid-falsify}); and an
AST-skeleton diversity analysis
($K_{\mathsf{ast}}{=}406$ on the $488$ blocks). \emph{Calibrated
scope.} On the real corpora ($488$ blocks plus the
$10$ upstream-faithful re-extracts) the per-feature ablation
is flat across all knobs: the only features that move
verdicts on real bugs are \textbf{device-consistency},
\textbf{gradient-flow}, and \textbf{low-confidence gating}
(three features, not five).  We accordingly scope the
empirical contribution to those three; we still describe
\emph{CEGAR contract discovery} and the
\emph{train/eval phase check} in
\Cref{sec:impl-cegar,sec:impl-phase} as engineering
no-ops (the analyser ships them but they cannot be
empirically distinguished from a smaller analyser on real
inputs), \emph{not} as contributions.  The localisation tracer
(\texttt{src/v5/localization.py}) is a shipped artefact rather than
a contribution claim; we report it in \Cref{sec:eval-loc-hybrid} as
engineering, not as a research result.
\textbf{(C6)} A Lean~4 \emph{operator-rule audit} of the
\textbf{shape-transfer rule table}: $28$
shape-transfer rules with $11/11$ previously-axiomatic
soundness lemmas closed sorry-free, the full
\texttt{lean/TensorGuard/} tree building \texttt{sorry}-free
under \texttt{lake build}, and
$28{,}000/28{,}000$ in-envelope samples agreeing with
\texttt{torch~2.9.1} (\Cref{sec:eval-lean};
\Cref{tab:handler-soundness}). \emph{The rule table is
audited; the analyser implementation, AST extractor, and
backward verifier are \emph{not} audited.}
