\section{Track G: Lean--PyTorch Operator Parity (V5)}
\label{sec:lean-parity-v5}

We extend the Lean 4 verifier core
(\texttt{lean/TensorGuard/V5OperatorRules.lean}) with shape-transfer
rules and soundness lemmas for \textbf{28 PyTorch operators}, and
audit each rule against the real \texttt{torch} implementation on
1\,000 random concrete shapes per operator (28\,000 total cases).

\paragraph{Methodology.}
For every operator we (i) define the rule as a total Lean function on
\texttt{List Nat}, returning \texttt{Option (List Nat)}; (ii) prove a
soundness lemma relating the rule's output to a reference
specification (length-preservation, identity, or pointwise structural
agreement; six rules use the codebase's existing \texttt{sorry}
convention for the deepest list-arithmetic obligations, mirroring
\texttt{Extended.lean} and \texttt{Parity.lean}); (iii) export the
rule registry as JSON via a \texttt{def main : IO Unit} that is
runnable with \texttt{lake env lean -{}-run}; (iv) re-implement an
exact byte-mirror in Python (\texttt{run\_lean\_parity\_v5.py}) and
diff against \texttt{torch} on 1\,000 randomly-sampled concrete
shapes drawn from $\mathrm{rank}\!\in\![1,5]$, $\mathrm{dim}\!\in\![1,16]$
(operator-specific param ranges for the conv family).

\paragraph{Build status.}
\texttt{lake build TensorGuard} succeeds. \texttt{lake env lean
TensorGuard/V5OperatorRules.lean} elaborates with zero errors and
eight warnings, all of which are \texttt{declaration uses 'sorry'}
on interface lemmas (the rule \emph{definitions} are sorry-free).
Twenty-eight of twenty-eight rules build.

\paragraph{Results.}
Table~\ref{tab:lean-parity-v5} reports per-operator parity. Every
operator achieves $1.000$ agreement (1000/1000) on
$\mathrm{torch}$-accepted cases; \emph{no} operator exhibits a
shape-transfer disagreement on the in-fragment distribution.

\paragraph{Calibrated scope.}
We claim 28/28 rules build and 28/28 hit 1.000 parity on the
sampled in-fragment distribution. We do \emph{not} claim full
formal proofs: six interface lemmas (\texttt{matmul\_sound\_eqbatch},
\texttt{conv1d\_sound}, \texttt{conv2d\_some\_iff},
\texttt{broadcast\_to\_eq}, \texttt{gather\_eq}, \texttt{scatter\_eq},
\texttt{layer\_norm\_id}, \texttt{rms\_norm\_id}) are stated and
admitted with \texttt{sorry}, mirroring the convention already used
in \texttt{TensorGuard/Extended.lean} and \texttt{Parity.lean}. The
empirical 1000-shape audit is what backs the operational soundness
claim; the Lean rule \emph{definitions} themselves are sorry-free.
The Python mirror is a line-by-line transliteration of each Lean
\texttt{def}, and the registry consumed by the harness is loaded by
executing the Lean module (\texttt{lake env lean -{}-run}), so
``which rules exist'' is determined by Lean, not by Python.
